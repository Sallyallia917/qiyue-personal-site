AI 医患沟通自动化 ↗

真实业务项目

问题：在高频、非结构化的医疗沟通中兼顾回复准确性、场景适配与风险边界。

产品决策：把场景自动化评估、样本测试、Prompt / 规则迭代与人工接管边界放在同一条质量闭环中，而不是只优化单轮回复。

证据：项目场景梳理、回复规则与人工接管策略。准确率和业务效果数据暂不展示，待原始统计口径与个人负责范围核验。

EES 民宿酒店客户服务 Agent ↗

独立 AI 应用原型

问题：住客咨询可能涉及通用服务知识、个人订单信息、实时房态与安全风险，系统需要先判断信息来源与处理权限，再决定回答或转人工。

产品方案：围绕混合意图识别、规则路由、订单信息权限、多轮上下文与对话确认建单逐步迭代，明确公开知识、个人订单、动态房态和需人工处理事项的边界。

验证方式：测试设计覆盖意图路由、订单权限、多轮状态、工单生命周期与异常边界。README、当前代码版本及测试结果尚待统一核验，因此暂不展示版本号、测试条数和通过率。

范围边界：使用模拟门店与模拟政策；未连接真实 PMS / OTA / CRM，不读取真实订单或房态，不执行真实退款、派单或消息发送。

咖啡增长行动引擎 ↗

独立应用原型

问题：探索如何把消费者研究转化为会员触达、商品推荐与优惠决策。

设计：把决策层拆为可测试的确定性规则：会员分群、商品候选筛选 / 排序、优惠预算与折后毛利校验；大模型仅规划用于后续营销表达，不直接决定优惠风险。

评测：离线评测集包含 8 个合成案例，当前报告显示 8/8 通过预设规则判定，覆盖正常路径、受众边界、预算、无效商品、优惠券匹配、结构校验与 API 故障场景。该结果验证当前评测器和固定样例，不代表真实营销效果或线上转化提升。

状态：已形成确定性业务决策与 LLM 文案生成的分层链路；后续仍需扩大评测集、补充盲评 / 人工评分，并用真实业务数据验证策略效果。

行业研究与商业机会识别 ↗

独立研究方法

问题：如何从用户需求出发，穿透行业供给、产业链分工与价值分配，识别值得产品化的问题？

方法：形成“需求—供给—产业结构—资源与权力—商业模式—产品机会”的分析路径，区分公开事实、推断与待验证假设。

应用：用于衣食住行需求研究、民宿与连锁酒店服务系统比较，以及企业客户服务与 AI 应用机会识别。此项为独立研究，不表述为已完成的企业付费咨询项目。
