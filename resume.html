主要项目

EES 酒店与民宿 AI 智能服务工作流系统 ↗

独立 AI 应用原型 · 2.0.5

业务问题：住客服务请求横跨公共知识、个人订单、动态房态、现场服务与安全事件；传统 FAQ 与人工处理割裂，重复反馈、订单权限和工单进度难以统一管理。

产品与架构：设计 Streamlit 对话入口与 Conversation Orchestrator，组合规则 + LLM 混合意图识别、RAG、Context Manager、BookingService 与 TicketService；明确知识问答、订单只读校验、业务规则和人工处理的职责边界。

领域建模：设计订单与工单分离的服务流程，覆盖用户确认、工单幂等去重、同订单不同问题并行、活动 / 终态管理、状态流转、发票申请及安全事件升级；采用 SQLite 演示持久化，防止重复建单和非法状态迁移。

质量验证：当前 2.0.5 分支自动化评测 288 项通过（Pytest 151、RAG 22、Routing 37、Hybrid Routing 78）。另完成 10 项端到端 UI 场景验收：UI01、UI02 完全符合；UI09 首轮澄清符合但改期提交失败；其余场景仍有缺陷，已形成下一轮修复清单。

产品规划：识别上下文与工单状态分离、缺少跨分类事件关联、UI 提交链路可观测性不足等结构性问题，提出 Incident 事件中心、工作流状态机、API 解耦与 trace 追踪的 2.1 演进方案。

边界：当前为演示原型，使用模拟订单和本地数据；未接入真实 PMS / OTA / CRM，不执行真实退款、改期、开票或人员派单。自动化测试通过不等同于 UI 全流程通过或生产效果验证。

证据：项目场景梳理、回复规则与人工接管策略。准确率和业务效果数据暂不展示，待原始统计口径与个人负责范围核验。

咖啡增长行动引擎 ↗

独立应用原型

问题：探索如何把消费者研究转化为会员触达、商品推荐与优惠决策。

设计：把决策层拆为可测试的确定性规则：会员分群、商品候选筛选 / 排序、优惠预算与折后毛利校验；大模型仅规划用于后续营销表达，不直接决定优惠风险。

评测：离线评测集包含 8 个合成案例，当前报告显示 8/8 通过预设规则判定，覆盖正常路径、受众边界、预算、无效商品、优惠券匹配、结构校验与 API 故障场景。该结果验证当前评测器和固定样例，不代表真实营销效果或线上转化提升。

状态：已形成确定性业务决策与 LLM 文案生成的分层链路；后续仍需扩大评测集、补充盲评 / 人工评分，并用真实业务数据验证策略效果。

行业研究与商业机会识别 ↗

问题：从用户需求出发，穿透行业供给、产业链分工与价值分配，识别值得产品化的问题。
