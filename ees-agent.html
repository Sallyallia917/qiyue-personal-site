客服助手

从“回答问题”走向“理解用户状态并采取行动”，探索酒店 / 民宿客服 Agent 的情绪与行动决策。

场景酒店 / 民宿客服
核心问题情绪 × 意图 × 行动
工具Dify / Coze
关键词Agent / Fallback / Action
01　场景与问题

真实服务里，情绪、紧迫程度和真正诉求同样决定下一步动作。

  • 用户可能处于担忧、愤怒、着急或困惑状态。
  • 只生成知识库答案，无法回答“现在应该做什么”。
02　关键判断

第一层能力定义为“状态理解”，第二层才是“答案生成”。

  • 识别 担忧 / 愤怒 / 紧急 / 困惑。
  • 判断真实意图。
  • 决定回答、补充信息、转人工或触发后续服务。
03　产品设计

输出结构不再只是文本，而是 理解 → 行动 → 解决。

  • 理解：确认问题与状态。
  • 行动：决定下一步。
  • 解决：生成场景回复。
  • 异常兜底：置信度不足或风险升高时退出自动化。
04　实现路径

用 Dify / Coze 验证 Agent 流程，把复杂逻辑拆成可快速试验的节点。

  • 先验证路由与情绪识别的业务价值。
  • 通过状态组合测试回复与行动是否一致。
  • 把“不能确定”设计成产品能力。
05　复盘与洞察

Agent 与普通 Chatbot 的分界线，不在于 Prompt 数量，而在于系统是否拥有“判断下一步做什么”的能力。
