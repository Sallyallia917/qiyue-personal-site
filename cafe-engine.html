STAR / 项目概览

把消费者研究转化为受业务规则约束的营销决策流程。

S · Situation

业务情境

精品咖啡会员运营需要同时考虑会员状态、营销授权、商品偏好、库存、优惠门槛、预算与折后毛利；仅靠生成式文案无法保证活动方案可执行。

T · Task

产品任务

构建一个从活动目标与预算出发，能够筛选受众、推荐商品、校验优惠规则，并在约束通过后生成营销方案的可运行原型。

A · Action

关键行动

将分群、推荐、优惠券预算和商品适配规则封装为确定性服务；再将结构化结果交给 DeepSeek 生成文案，并对输出结构、商品 / 优惠 ID 和不受支持的数字声明进行校验。

R · Result

阶段结果

形成 Streamlit 活动决策原型与离线评测套件；8 个合成评测案例全部按预期识别通过 / 失败。该结果验证的是评测器与规则约束，不代表真实复购、转化或 ROI 提升。

01 / 业务建模

营销决策必须同时满足用户适配与商业约束。

  • 会员分群：基于会员偏好、最近购买间隔、订单数和营销授权筛选目标人群；未授权用户排除在营销触达之外。
  • 商品推荐：结合品类偏好、价格、成本和库存形成候选商品。
  • 优惠校验：计算目标受众与预期核销率下的优惠成本，检查活动预算、券预算、最低消费门槛及折后毛利。
  • 生成约束：模型只接收已经过规则筛选的结构化上下文；不能自行添加未授权商品、无效优惠券或无依据的数字承诺。
02 / 技术架构

02A / 可复现业务决策示例

以“唤醒沉睡会员”为例，先计算受众与优惠成本，再决定是否交给模型生成。

使用仓库中的合成会员、商品和优惠券数据，设定活动预算 1,000 元、目标分群“沉睡待唤醒”、预计核销率 30%，选择优惠券 C001（满 100 减 10）。当前规则筛选得到 18 名符合授权且满足沉睡分群条件的会员。

18 人授权且符合分群条件的目标会员
5.4 单预计核销量：18 × 30%
54 元预计优惠成本：5.4 × 10 元
  • 预算约束：优惠券预算为 300 元，活动预算为 1,000 元，实际校验上限取两者较小值；本例预计优惠成本 54 元，未超过预算上限。
  • 商品约束：候选商品需有库存、价格与成本数据合法；单件商品售价需达到 100 元门槛，且折后毛利不得为负。购物车多商品是否满足门槛仍需真实订单总额验证。
  • 生成约束：只有通过规则校验的优惠券和商品候选才进入 LLM 上下文；模型不能自行创造商品、优惠券或数字承诺。

以上人数和成本由仓库合成数据及明确输入条件计算，用于展示规则链路，不代表真实会员、实际活动支出或业务效果。实际商品推荐名单仍以系统运行输出为准。

04 / 产品复盘

把商业判断写成可执行规则，比让模型自由生成更重要。

项目将消费者研究作为业务假设来源，再把营销授权、受众筛选、商品可售性、预算和毛利等约束转化为系统规则。模型只承担适合生成式 AI 的表达任务，商业底线由确定性逻辑把关。

PRODUCT PRINCIPLE

先让业务决策可解释、可校验，再引入生成能力；先证明系统不会越过商业约束，再讨论它能否创造增长。

04A / 商业效果验证设计

不把优惠成本当作 ROI；先定义增量贡献，再计算活动回报。

活动总成本 = 实际核销优惠成本 + 媒体 / 触达成本 + 运营人力成本 + 模型 API 成本。

增量毛利贡献 = 实验组相对对照组的增量订单数 × 单笔订单贡献毛利。

ROI =（增量毛利贡献 − 活动总成本）÷ 活动总成本。

盈亏平衡订单数 = 活动总成本 ÷ 单笔订单贡献毛利。

当前原型没有真实触达、核销、订单归因或对照组数据，因此只能提供计算口径和实验设计，不能报告实际 ROI。后续应采用随机对照或可解释的准实验方案，区分自然复购与活动带来的增量。

05 / 下一阶段

从离线规则验证走向真实活动效果验证。

  • 补齐端到端流程：让输入、受众、商品、优惠、生成文案与评测报告可复现。
  • 建立模型对照：同一业务上下文下比较规则模板与 LLM 方案，记录结构合规、事实约束、人工可用性、延迟与重试。
  • 接入真实业务数据：在授权和脱敏前提下接入会员、订单、商品与库存数据。
  • 验证商业结果：具备曝光、核销和订单归因及合理对照设计后，再评估复购、毛利和 ROI。
